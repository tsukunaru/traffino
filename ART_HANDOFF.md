# Traffino — передача на этап графики

Сначала прочитать README и прогнать `npm test`. Этап 2 реализован; актуальные файлы и художественные решения описаны в `VISUAL_INTEGRATION.md`, `ART_STYLE_GUIDE.md`, `AUDIO_STYLE_GUIDE.md`. Ниже сохранён контракт ядра с представлением. Модели и звук создаются кодом и не требуют внешних CDN.

## Координаты и размеры

Игровая плоскость X/Z; Y — высота. Север соответствует отрицательному Z, восток положительному X. Направления `0=N, 1=E, 2=S, 3=W`; `turn 0=straight, 1=left, 2=right`. Одна единица приблизительно соответствует метру. Положение автомобиля — центр. Локальный нос модели должен смотреть вдоль +Z. Угол по Y — `atan2(dx,dz)`.

Габариты для коллизий берутся из `VEHICLES.length / width` и не должны считываться из визуального bounding box. Если художественная модель немного крупнее, менять её масштаб. Если задуманы новые реальные габариты — менять конфигурацию и снова проверять торможение, очереди и маршруты.

Пешеход — примерно 1,05 единицы высоты, машина 2,5–4,8 длины. Стоп-линия находится перед входом и переходом. Не закрывать зданиями и деревьями подходы, знаки намерения, людей и стоп-линии.

## Точки подключения

| Будущий компонент | Точка сейчас | Данные |
|---|---|---|
| VehicleView | `CityView.render`, `models/cars/lights/wheels/hubs` | `id`, `serial`, `kind`, позиция, касательная, скорость, состояние, манёвр, экстренный таймер |
| CharacterView | `CityView.character`, `uniform`, `arm`; `App.event` | команды, опасности, столкновения, высокий поток; косметический ID |
| IntersectionView | `CityView.buildEnvironment`, `bind` | определение карты, маршруты, матрица конфликтов |

| EnvironmentView | `environment` | район и состояние события |
| PedestrianView | `CityView.people`, `person` | общий instanced-пул из семи деталей на человека, переходящие и ожидающие у каждого перехода |
| TimeOfDayView | `timeOfDay`, `day`, текущие светильники | непрерывное значение 0…1; оттенки света и окружения интерполировать |
| EventView | `eventBarrier`, баннеры, `App.event` | тип, направление, стадия, оставшееся время |
| Audio | `AudioSystem` | состояния музыки, шины Master/Music/SFX/UI/Traffic/Ambience |

Для финальных моделей можно заменить instanced-части на заранее созданные группы из GLTF, сохранив пулы. Не создавать / уничтожать графические объекты на каждом spawn/despawn. Разные `serial` у того же `id` означают повторное использование слота — сбросить локальную анимацию и эффект.

## События симуляции

Все приходят в переданный конструктору `Simulation` обработчик `emit(name, payload)`. Сейчас `App.event` распределяет их между звуком, прогрессом и представлением. При добавлении визуальных обработчиков оставлять существующее начисление наград в модели прогрессии.

| Событие | Payload | Возможный визуальный эффект |
|---|---|---|
| `directionOpened` | `{direction}` | жест регулировщика, смена лампы, короткий отклик |
| `directionClosed` | `{direction}` | запрещающий жест, красная лампа |
| `danger` | `{direction,active}` | начало / конец предупреждения, реакция регулировщика; только при изменении состояния |
| `vehicleSpawned` | ссылка на pooled vehicle | выбор модели и окраски, начало дорожного звука |
| `vehiclePassed` | ссылка на vehicle | ненавязчивый счётчик, реакция персонажа |
| `emergency` | vehicle | маячок и предупреждение нужного направления |
| `reckless` | vehicle | постоянный читаемый значок лихача |
| `emergencyFailed` | vehicle | задержка без уничтожения партии |
| `pedestriansStarted` | `{direction,count}` | разрешающий жест, запуск походки |
| `pedestrianPassed` | person | завершение походки, возврат отображения в пул |
| `jam` | `{direction}` | тревога, сигнал очереди; реальное оставшееся время читать из очереди |
| `collision` | `{x,z,pedestrian}` | пыль / знак ошибки / тряска; без натуралистических деталей |
| `highFlow` | `{flow}` | реакция персонажа и мягкое усиление музыки |
| `day` | `{day}` | новый день; непрерывное освещение не переключать резко |
| `eventWarning` | event | заблаговременное объявление и маркер места |
| `eventStarted` | event | дорожные работы, эвакуатор, очередь доставки |
| `eventEnded` | event | убрать ограничения, закрыть связанные эффекты |
| `ended` | `{reason,stats}` | остановка игры, переход к результату |

Vehicle/person/event payload — живые объекты, которые переиспользуются. Для отложенного эффекта копировать нужные числа и `serial`, не удерживать ссылку на «вечную» машину. Опасность обновляется с частотой 10 Гц; событие `danger` приходит только при изменении состояния направления. Высокий поток уведомляется на успешных проездах, поэтому не перезапускать длинную анимацию на каждом уведомлении.

## Анимации

- Скорость колёс и небольшой наклон корпуса вычислять из `speed`, `dx/dz`, изменения скорости; анимация не перемещает игровой центр.
- При `Waiting` машина стоит, при `Starting` плавно разгоняется; `Crossing` уже имеет безотзывное разрешение закончить путь.
- `Crashed` остаётся на месте до эвакуации. Не уменьшать время физического препятствия только потому, что VFX закончился.
- Персонаж может смешивать idle / open / stop / danger / collision / high-flow. Его положение сейчас на безопасном углу, а не на траектории транспорта.
- Окна зданий, фонари и вывески считывают `timeOfDay`; декоративные прохожие не должны менять статистику или перекрывать знаки реальных пешеходов.

## Материалы и эффекты

Сохранять различимость красного и зелёного также текстом / формой. Экстренные машины выделяются маячком и HUD-таймером; лихач — отдельным предупреждением. Маршрут первой машины доступен независимо от красоты модели. На mobile кнопки отнесены от полос, не сдвигать их поверх транспорта при смене камеры.

Каждый частый эффект — заранее ограниченный пул. Для low quality выключать декоративные тени, отражения и частицы, но сохранять все предупреждения и игровых пешеходов. Изменение частоты рендера не меняет fixed step. При скрытии вкладки, рекламе и паузе выключать все звуковые источники и не продолжать анимации, влияющие на восприятие положения машин.

Sound pass реализован через PCM-генераторы `sound.js` и кэш `AudioSystem`. Не создавать новый несвязанный AudioContext: существующая общая пауза управляет всем звуком. Шесть состояний музыки стартуют синхронно и плавно смешиваются.

## Критерии приёмки второго этапа

1. `npm test` и `npm run package` проходят после замены визуала.
2. По-прежнему понятны сторона, манёвр первой машины, STOP/GO, экстренный таймер и пешеходы.
3. Читаемы 390×844, 844×390, 1280×720, 4:3 и широкое окно; safe-area учтена.
4. Фоторежим вращает и масштабирует камеру без движения симуляции; после скрытия интерфейса кадр чистый, касание возвращает управление.
5. Нет дополнительных runtime-CDN, всплывающих окон, незагруженных ассетов или DEV-кода в ZIP.
6. Измерены FPS и память на физическом слабом Android и iPhone; после 10–15 минут пул не растёт.
7. Финальные рекламные изображения и материалы магазина делаются по реальному обновлённому игровому виду.

Графический этап теперь реализован. Пункт о физических мобильных устройствах остаётся отдельной проверкой перед выпуском; локальные проверки выполняются в Chrome/SwiftShader.
