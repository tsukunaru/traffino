# Traffino — приёмка первого этапа

Это сохранённый отчёт первого этапа. Актуальная реализация графики и звука версии 0.2 описана в `VISUAL_INTEGRATION.md`; соответствующие снимки и отчёты находятся в `artifacts/`.

Дата: 21 сентября 2026. Объём: игровой код, проходимый сценарий, техническое представление, интеграционный слой Яндекса, сборка и передача на художественный этап. Финальная графика и публикация не входят в этот результат.

## Воспроизводимые проверки

`npm test` — 33 проверки механик, данных, прогрессии, платформы и звука. `npm run profile` — все сюжетные seed, медали, час пик и нагрузка. `npm run test:browser` — полная цепочка экранов и метапрогрессии; `npm run test:browser:production` — независимый запуск итогового кода, адаптивность, ввод, паузы, фоторежим, локализация, отсутствие DEV и fallback без платформы. `npm run package` повторяет тесты, создаёт production и проверяет состав архива.

Отчёты:

- `artifacts/verification.json`: результаты смен, seed, статистика и CPU-замеры.
- `artifacts/browser-development.json`, `artifacts/browser-production.json`: выполненные браузерные проверки, размеры и ошибки консоли.
- `artifacts/production-menu.png`, `production-mobile.png`, `production-landscape.png`: реальные кадры production в Chrome.
- `artifacts/release.json`: размер, состав и SHA-256 `traffino-yandex.zip`.

Браузерные сценарии покупают и сбрасывают прогресс только во временном тестовом профиле. Бот не обходит столкновения и заторы; неуязвимость применяется только в отдельно помеченном нагрузочном прогоне. Числа медалей и времени берутся из отчёта, а не задаются тестом.

## Границы подтверждённого результата

Локальная часть первого этапа реализована и проверена. Это не утверждение о прохождении модерации или выполненном втором художественном этапе.

До публикации нужны реальные прогоны в черновике Яндекс Игр: реклама и её возврат фокуса, облако между устройствами, смена аккаунта, серверная дата и таблицы рекордов, настройки карточки. Локальные SDK-моки проверяют поведение нашего кода, а не доступность внешних сервисов.

Нужны замеры на физическом слабом Android и iPhone и проверка старых целевых браузеров. CPU-профиль Node и software WebGL в Chrome не доказывают 60 FPS на телефоне. ES5-трансформация, polyfills, WebGL 1 и CSS-fallback обеспечивают техническую основу, но не заменяют эти прогоны. Пулы ограничивают число объектов; абсолютный нулевой GC для браузера / DOM / Three.js не заявляется.

Финальный баланс удовольствия, скорость понимания и художественная читаемость проверяются живым игроком после следующего этапа. Одновременные траты валюты с разных устройств пока используют целый наиболее свежий снимок сохранения; серверные транзакции не реализованы. Текущая графика рисует четырёхстороннюю карту; нестандартные топологии уже поддержаны правилами и потребуют соответствующего оформления.
